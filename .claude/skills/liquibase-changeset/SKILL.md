# Liquibase changeset

Ground rules from `.claude/docs/refactoring-plan.md`:
- Every schema change gets a **new** `db.changelog-X.Y.yaml`.
- Every changeSet has a `rollback`.
- Existing changelogs are **never edited**.

None of the existing changelogs (`1.0` → `2.3`) has a `rollback` block, so do not copy their shape blindly.

## Project facts
- Changelogs live in `src/main/resources/db/changelog/`, and `db.changelog-master.yaml` includes them in order. Liquibase 4.4.0 runs them at context startup through `config/LiquibaseConfig`.
- Database by environment:
  - Tests (`test` profile): embedded H2GIS (`src/test/.../config/EmbeddedDataSourceConfig`).
  - Production: PostgreSQL/PostGIS.
- JPA entities are in `src/main/java/com/github/swrirobotics/persistence/`. The metamodel (`Bag_`, ...) is generated by `hibernate-jpamodelgen` at compile time. Never edit it by hand.

## Procedure
1. **Pick the version.** Read `db.changelog-master.yaml` and the highest-numbered changelog. The next version follows it: after `2.3` comes `2.4`.
2. **Create `db.changelog-<X.Y>.yaml`:**
   - Start with a comment that says *why*, like `db.changelog-2.3.yaml`.
   - Use one `changeSet` per logical change, with a descriptive kebab-case `id`.
   - For `author`, use the committer's `git config user.name` unless the user specified a different author.
   - Give every changeSet an explicit `rollback:`, even where Liquibase could auto-generate one.
   - Put PostgreSQL-only DDL (e.g. `pg_trgm` GIN indexes) behind a precondition so H2 skips it:
     ```yaml
     preConditions:
       - onFail: MARK_RAN
       - dbms:
           type: postgresql
     ```
   - Compute data-dependent values from the data. For example, sequences must start at `max(id)+1` (step 33).
3. **Register the changelog.** Append an `include` for the new file at the **end** of `db.changelog-master.yaml`.
4. **Update entities.** If an entity changes, update it in `persistence/`, and keep its mapping consistent with the DDL.
5. **Verify.**
   - Run the H2 chain: `mvn test -Dtest=BagRepositoryTest`, then `mvn -B package`.
   - From step 16 on, run the same tests under the PostGIS Testcontainers profile. Before step 16, state in the PR that only H2 was verified.
   - **Rollback check:** apply the changelog, then roll it back once, against a disposable database. The pom has no `liquibase-maven-plugin`, so the command is not established yet. Ask the user whether to add the plugin or to use the Liquibase CLI against a docker-compose PostGIS. Record the chosen command in this skill.
6. **Failures.**
   - If the change fails on H2 only or on PostGIS only, add a `dbms` precondition. Do not change the semantics.
   - A checksum error on an *existing* changelog means it was edited. Revert that edit.

## Safety
- Destructive DDL needs explicit user confirmation and a `CHANGELOG.md` note. Example: step 17 drops `SPRING_SESSION*`, which logs every user out.
- Never run changelogs or rollbacks against a non-disposable database.
